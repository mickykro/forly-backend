The problem is downstream, in n8n:

Live inspection of the n8n account traced the chain: Main Router v3 (fhyTsd1DSN6wtMGz) → Business Handler v6 (lQwn7eYSuIxAZkJB, updated Oct 4 — this has replaced "Business Handler2" as the live handler since the last report) → Forly Property Intake (HTTP call to this backend) → Handled by Forly? The IF node has no idea why the backend declined — an away-message and an ordinary "hi, what can you do?" look identical to it — so every bounced-back auto-reply reaches the AI Agent and burns one real LLM generation plus one outbound WhatsApp send for a question nobody asked.

Fix: add a guard in front of AI Agent - Business1 in Business Handler v6 that mirrors this repo's own AUTO_REPLY_RE (server/property-draft.js) — same intent, same place in the pipeline this backend already solved it in, just on the other side of the HTTP call.
