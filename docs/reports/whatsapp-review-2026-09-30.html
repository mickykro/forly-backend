Found and fixed

Fixed "1" / "2" ignored right after a photo batch — the menu that follows had no idea buttons were sent

נופר הרוש שמאות מקרקעין, 972546582548 — Sep 29, 18:15–18:17

Three images landed, bringing the draft to 7 photos and to the "preview or create?" question. The agent answered with the numbers on the buttons — exactly what every other numbered menu in this bot accepts — and got the identical question back twice, verbatim, before falling back to typing the word itself:

שמרתי 7 תמונות לנכס. ... 1 · תצוגה מקדימה | 2 · ליצור
1
כל הפרטים והתמונות אצלי ✅ ... (same menu, "1" not recognized)
2
כל הפרטים והתמונות אצלי ✅ ... (same menu again)
ליצור
איזה עיצוב לדף? ...

Numbered replies are resolved by mapping "1"/"2" back through draft.last_buttons, which routes/whatsapp.js saves from whatever the previous reply's buttons were. The message that asks "preview or create?" right after a photo batch is built by photoTimer() in server/photo-choice.js — and that function only returned the updated draft when photos had been dropped for exceeding the 12-photo cap (the overwhelmingly rare case). Every ordinary batch got draft: undefined back, so nothing was saved — last_buttons stayed stale, the digit never resolved, and the agent's numbered answer landed as plain text that matched nothing.

photoTimer() now always returns the touched draft, matching every other reply path in the file. Added a regression test in whatsapp-intake.test.js that reproduces this exact conversation (photos → photo_timer → "1") and fails without the fix.

fix(whatsapp): photo timer must return the draft even when nothing was dropped

n8n Declining the "build from these photos?" offer sometimes gets an answer this codebase never sends

נופר הרוש שמאות מקרקעין, 972546582548 — Sep 30, 05:25

The agent replied "2" (לא) to ערכתי 7 תמונות ✨ לבנות מהן דף נכס?. This backend's code for that exact case is declined(), which always answers "בסדר, לא בונים דף מהתמונות האלה." — that string doesn't exist anywhere in this repo. What the agent actually got back was:

2
בוחרת את סגנון אטלייה 🎨 עכשיו התמונות — שלח לפחות 4 תמונות של הנכס

"בוחרת" (feminine "choosing") and an unprompted template pick don't match any reply in whatsapp-replies.js. This backend does delete the draft on decline (del: true), so the most likely explanation is a separate n8n flow independently listening for the same "2" and answering on top of (or instead of) this backend — worth checking the Main Router for a competing handler that fires when there's no open draft right after a decline.
