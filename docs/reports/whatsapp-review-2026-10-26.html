2 · Agent's own logo photo was treated as a property photo — wasted generation, near-miss bad page New

An agent sent their business logo, explicitly captioned "זה הלוגו שלי" ("this is my logo"). The bot ran it through the property-photo "improve" pipeline anyway:

10-22 10:42 — Agent sends logo image, caption: "זה הלוגו שלי"
10-22 10:43 — Bot: "עובדת על התמונה ✨ כל אחת תגיע כשהיא מוכנה" (working on it)
10-22 10:43 — Bot sends back an "edited" version with caption: "שיפרנו את איכות הלוגו שלנו 🎯 תאורה משופרת וניקיון מושלם. הרים של זהב בברקה חדשה ✨ #בנו #לוגו #עיצוב #איכות #elk" — a nonsensical, hallucinated caption ("golden mountains in a new sparkle") that has nothing to do with a logo
10-22 10:43 — Bot: "ערכתי תמונה אחת ✨ לבנות ממנה דף נכס?" (I edited one image — build a property page from it?) → Agent replied "1" (yes)

This burns a full paid image-edit generation on an image that was never a property photo, produces a caption that is visibly wrong (a trust problem if the agent had posted it), and then — worse — offers to build an entire property listing page from a company logo. No check exists for "is this actually a property photo" before either the generation or the page-build offer.

Recommended fix: a cheap pre-check (even a keyword check on an accompanying caption like "לוגו"/"logo", or a lightweight vision classification) before spending a generation on an uploaded image, and definitely before offering to build a page from it.

3 · The bot's own valid menu option was rejected twice New

Not a paraphrase-matching gap — this time the literal digit from the bot's own just-sent menu failed to match, twice:

10-20 10:22 — Bot: "קיבלתי 12 תמונות 📸 מה לעשות? ... 3 · לשפר את כל 12 התמונות"
10-20 11:50 — Agent: "3" → Bot: "לא בטוחה למה התכוונת 🙂" (!)
10-20 11:50 — Agent spells it out: "לשפר את כל ה12" → Bot: "לא בטוחה למה התכוונת 🙂" again
10-20 11:51 — Agent resends all 12 photos a second time; bot re-offers the same menu; agent replies "3" again → this time it works

The ~88-minute gap between the menu being offered (10:22) and the first "3" (11:50) suggests the pending-menu state had expired or been cleared by then, leaving a bare "3" with nothing to match against — but the bot's fallback gives no hint of that; it reads exactly like the bot never saw the images at all, which is a much worse signal to the agent than an honest "that request has expired, please resend."

Recommended fix: when a numeric reply can't be matched to any currently-active menu, say so explicitly ("that offer expired — please resend your photos") instead of the generic "didn't understand," and consider whether the photo-batch menu's state should persist longer than it currently does.
