Fixed this cycle — unrelated to the outage

Fixed A one-field aside about a different field than the one asked could corrupt the question

server/whatsapp-intake.js activeTurn() — reproduced against two real transcripts (972526003708, 2026-09-30; 972508505321, 2026-10-08)

The bug: when an agent's reply names a field other than the one being asked (e.g. a price correction — "רגע, המחיר האמיתי הוא..." — sent while "floor" is open, or "למכירה כמובן" sent while "rooms" is open) and the AI extractor can't parse anything useful out of that short aside, the code fell through to the asked field's own parser on that same text. A stray number from the other field (e.g. a price) could then be read as a floor, or free text with no digits at all produced a flat-out wrong "לא הצלחתי להבין" (couldn't understand) on a question the agent never actually answered — exactly what two real conversations show.

The fix: when the extractor returns nothing and the text named exactly one field, different from the one asked, the turn now re-asks the open question instead of forcing the mismatched text through that field's parser. Nothing is saved, no bogus retry state is set, and the agent sees the same question again rather than a confusing rejection. Covered by a new regression test in server/whatsapp-intake.test.js (confirmed to fail against the old code, pass against the fix); full server test suite re-run clean aside from the pre-existing, unrelated utils.test.js sandbox DNS limitation noted in PR #115.
